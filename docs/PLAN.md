# MoneyMore 量化系统规划

## 1. 项目目标

MoneyMore 是面向个人投资者的 A 股量化研究与模拟交易系统。当前阶段不接入程序化实盘交易，重点是建立一条可审计、可复现、可持续运行的研究链路：

```text
点时数据 → 因子注册表 → 横截面预测分数 → Top-K组合
       → Qlib risk_degree择时 → 风险约束 → 次日开盘模拟撮合
       → 成交对账 → 前瞻证据归档 → 前台观测
```

系统以 Qlib 的分层思想和策略接口为主体，但保留 MoneyMore 自己的 A 股数据、撮合、账本和服务端实现：

- Qlib负责定义研究范式：特征、预测分数、组合策略、动态风险度、回测评价和模型治理；
- MoneyMore负责点时数据、A股交易规则、模拟订单、持仓账本、每日流水线和产品页面；
- 后续模型可以接入原生Qlib训练器，不改变组合、执行和观测接口。

当前只运行 `PAPER_ONLY` 模式。券商接口不在本阶段范围内。

## 2. 核心架构

### 2.1 数据层

- Tushare为当前主数据源；
- 原始响应按来源、表名和批次不可变保存到 `data/raw`；
- 去重后的研究表保存到 `data/processed`；
- 财务数据按公告可用日期进入因子，禁止按报告期回填未来信息；
- 复权价格用于信号，未复权开盘价用于模拟成交；
- 历史股票池保留当期成员，降低幸存者偏差；
- ETF权限尚未开通，当前研究范围是A股个股。

### 2.2 因子与预测分数

因子体系采用Qlib式“特征注册—统一预处理—横截面评价”流程：

- 因子注册表目前包含21个价格、估值、基本面和分红因子；
- 低值更优因子统一反向；
- 每个交易截面执行去极值和标准化；
- 使用Rank IC、ICIR和分层收益评估；
- 样本内与样本外分别报告；
- 2022年后的历史已参与开发判断，不能再称为纯净测试集。

当前银行模型：

```text
bank_multifactor_no_quality_candidate

价值      47.0588%
防御      29.4118%
动量      23.5294%
质量       0%
```

质量组暂时保留在注册表和报告中，但在当前候选模型中权重为零。

### 2.3 Top-K组合策略

Top-K本身属于交易策略，而不只是选股列表。它规定：

- 调仓频率：按研究日历生成截面信号；
- 目标数量：Top 8；
- 持仓缓冲：持仓排名未跌出12名时允许继续持有；
- 换仓限制：每期最多正常替换2只；
- 基础单股权重：银行子账户10%；
- 基础组合风险度：80%；
- 成交时点：T日收盘后生成目标，T+1开盘模拟成交。

Top-K回答“买卖哪些股票”。组合总体是否使用80%风险预算，由Qlib式 `risk_degree` 择时层回答。

### 2.4 Qlib式交易择时

MoneyMore采用与Qlib `BaseSignalStrategy.get_risk_degree()`一致的语义：

```text
risk_degree = 投入风险资产的组合资金比例
```

最终单股目标权重：

```text
最终单股权重 = Top-K基础权重 × risk_degree ÷ 基础风险度
```

已建立三个同口径基线：

1. `fixed_80`
   - 固定风险度80%；
   - 作为不择时对照组。

2. `kama_10_2_30`
   - Kaufman自适应移动平均线的多头/现金切换；
   - 历史结果明显劣化；
   - 仅保留为被拒绝基线，不作为当前模拟策略。

3. `vol_target_12`
   - 60日实现波动率；
   - 年化目标波动率12%；
   - 风险度限制为20%～80%；
   - 以10个百分点为台阶，每20个交易日重新评估；
   - 当前状态为 `PROSPECTIVE_CANDIDATE`。

历史对比：

| 策略 | 区间 | CAGR | 最大回撤 | 夏普 |
|---|---|---:|---:|---:|
| fixed_80 | 样本内 | 1.62% | -25.68% | 0.18 |
| fixed_80 | 样本外 | 10.31% | -14.81% | 0.93 |
| kama_10_2_30 | 样本内 | -2.93% | -26.70% | -0.11 |
| kama_10_2_30 | 样本外 | 2.46% | -14.30% | 0.31 |
| vol_target_12 | 样本内 | 1.91% | -17.08% | 0.20 |
| vol_target_12 | 样本外 | 10.49% | -15.64% | 0.95 |

以上历史均已被研究过程使用，只能作为验证证据。`vol_target_12` 是否真正优于固定仓位，必须由2026-07-27之后的前瞻模拟继续判断。

### 2.5 风险与权重优化

当前阶段采用：

- Top-K等权；
- 单股基础权重10%；
- 基础总风险度80%；
- `risk_degree`动态缩放；
- 组合最大回撤熔断；
- 交易费用、滑点、整手和涨跌停限制。

后续可在Top-K之后增加Qlib增强指数或Riskfolio风险预算模块，比较：

- 等权；
- 逆波动；
- 风险平价；
- 换手约束下的最小方差。

权重优化必须作为独立实验，不与选股和择时参数同时搜索。

### 2.6 模拟撮合与对账

PaperBroker使用独立账户 `bank_shadow`：

- 决策、委托、成交、持仓和现金分别记账；
- T日信号不允许T日成交；
- T+1开盘价加滑点撮合；
- 买入按100股整手；
- 计算佣金、最低佣金、印花税和过户费；
- 涨跌停或不可交易状态阻止对应方向成交；
- 每日完成订单、成交、现金和持仓对账；
- 对账不一致时流水线失败关闭。

## 3. 模型治理

模型状态统一为：

- `RESEARCH_ONLY`：仅供研究展示；
- `PROSPECTIVE_CANDIDATE`：参数冻结，开始累计前瞻证据；
- `PAPER_QUALIFIED`：达到模拟主策略门槛；
- `SUSPENDED`：数据、运行或表现异常，停止新增目标。

当前状态：

| 模块 | 状态 |
|---|---|
| 银行多因子V1 | `RESEARCH_ONLY` |
| 去质量组Top-K候选 | `PROSPECTIVE_CANDIDATE` |
| KAMA择时 | `REJECTED_BASELINE` |
| 12%波动率目标择时 | `PROSPECTIVE_CANDIDATE` |
| 银行影子账户 | `PAPER_ONLY` |

晋级原则：

- 参数和代码冻结后才开始计算前瞻表现；
- 至少覆盖一个完整调仓周期；
- 流水线、成交和对账不存在未解释差异；
- 与固定风险度基线比较收益、回撤、夏普和换手；
- 不允许只因历史收益较高而晋级；
- 修改核心因子、权重、择时参数或成交规则后重新开始证据周期。

## 4. 每日流水线

服务端每天18:30（Asia/Shanghai）运行，不依赖Codex自动任务：

1. 校验交易日；
2. 增量同步行情、估值、财务和分红数据；
3. 撮合前一交易日待执行委托；
4. 计算21因子并生成银行横截面分数；
5. 执行Top-K、Rank 12缓冲和最多2只替换；
6. 计算当前 `risk_degree`；
7. 生成下一交易日目标委托；
8. 完成现金、持仓、订单和成交对账；
9. 将不可变运行报告写入 `state/bank-shadow`；
10. 前台刷新组合、择时、订单和流水线状态。

## 8. M4.5 多行业统一影子组合——已完成

MoneyMore 已从银行专用影子账户扩展为五行业统一模拟账户：

```text
行业内因子排名
→ 行业 Top-K 与 risk_degree
→ 跨行业逆波动风险预算
→ 最终单股目标权重
→ multi_sector_shadow
→ T+1 开盘撮合
→ 综合持仓、现金和成交对账
→ 行业持仓与盈亏归因
```

最终单股目标权重采用：

```text
单股目标权重 = 行业风险预算 × 行业 risk_degree ÷ 行业内目标股票数
```

当前执行约束：

- 银行、红利、工业有色、芯片和创业板成长共享一个模拟资金账户；
- 账户名为 `multi_sector_shadow`，原 `bank_shadow` 仅保留为银行基线；
- T 日收盘后生成目标订单，T+1 开盘撮合；
- 卖单优先撮合，随后处理买单；
- 保留整手、现金、T+1、涨跌停、滑点和交易费用约束；
- 每日固化目标权重、订单、成交、持仓、现金、行业归因与对账结果；
- 对账不一致时流水线失败关闭。

## 9. 非因子建设路线图

以下任务全部纳入正式计划，按依赖关系顺序实施：

### M4.7 公司行为入账——进行中

- 权益登记日冻结持股数量；
- 现金分红按支付日进入现金账本；
- 送股和转增按上市日增加持股并摊薄成本；

- 公司行为进入现金、持仓和总账户对账；
- 前台展示权益登记与入账流水。

验收标准：现金和股份只入账一次，入账后综合账户仍能通过全量对账。

### M4.8 数据质量中心——已完成首版

- 数据表新鲜度、缺失交易日、重复记录和异常值检查；
- 行情、复权、财务、分红和ETF披露版本健康状态；
- Tushare失败重试、断点续跑与补数任务；
- 数据异常阻断订单并在前台解释原因。

已实现：

- 目标股票行情与复权因子必须更新到当日；
- 估值数据不得早于上一交易日；
- 财务公告日期和目标股票财务覆盖检查；
- 分红数据覆盖及公司行为主键检查；
- OHLC价格关系、正复权因子和各表重复主键检查；
- 行业模型评分必须更新到当日；
- ETF成分披露年龄检查；
- 日度健康摘要和逐项检查结果持久化；
- 任一 `BLOCK` 检查阻止旧订单撮合及新订单生成；
- 前台数据健康中心展示 `PASS/WARN/BLOCK`、影响股票和历史状态。

验收标准：当前20只目标股票全部检查通过，状态为 `HEALTHY`。

### M4.9 账户风险状态机——已完成首版

- `NORMAL`、`REDUCE_ONLY`、`SELL_ONLY`、`SUSPENDED`状态；
- 单股、单行业、总仓位、现金、波动率和回撤限制；
- 阻断动作、恢复条件和人工确认记录。

状态及权限：

| 状态 | 订单权限 | 典型触发 |
|---|---|---|
| `NORMAL` | 按模型正常买卖 | 全部检查通过 |
| `REDUCE_ONLY` | 不得增加任一股票风险，只能持平或降低 | 回撤预警、现金低于10% |
| `SELL_ONLY` | 所有模型目标临时降为0，只允许卖出 | 最大回撤、总仓位越界 |
| `SUSPENDED` | 取消全部待执行订单，不撮合、不生成新订单 | 数据质量阻断、对账失败 |

状态恶化自动升级；风险条件解除后只更新建议状态，生效状态必须经过前台人工确认才能降级。所有自动升级和人工恢复均写入不可变转换流水。

### M4.10 流水线恢复与通知——已完成首版

- 步骤级运行状态、重试、断点续跑和幂等恢复；
- 数据失败、对账失败、风险熔断、订单延期通知；
- 本地通知优先，外部通知适配器后置。

已实现：

- 每次日度任务拆分为 `bank_pipeline`、`sector_research`、`multi_sector_execution` 三个可审计步骤；
- 每个步骤失败后自动重试一次，并分别保留每次尝试的开始时间、结束时间与错误；
- 同一交易日补跑时，已成功步骤标记为 `SKIPPED_COMPLETED`，从首个未完成步骤继续；
- 流水线失败、数据质量阻断、风险暂停、对账失败、订单延期与恢复成功写入本地告警中心；
- 告警使用去重键避免重复轰炸，并支持前台人工确认；
- `/api/task-operations` 统一提供任务、步骤和告警审计数据，运维页展示恢复过程。

验收标准：制造一次可恢复故障时，步骤自动重试；再次触发同一交易日任务不会重复执行已完成步骤，且失败与恢复均有可确认的本地告警。

### M4.11 模型版本与前瞻证据——已完成首版

- 模型、配置、代码、数据截止日和股票池版本绑定；
- 信号关联具体模型版本；
- 参数变化自动开启新的证据周期；
- 历史诊断、前瞻模拟和正式影子版本明确隔离。

已实现：

- 新增不可变模型注册表，版本 ID 由模型标识、生命周期、证据阶段、数据截止日、股票池、配置文件和代码文件的 SHA-256 指纹共同生成；
- 任一代码、配置、股票池或数据截止日变化都会产生新版本，不允许原地覆盖；
- 每个版本生成独立 JSON manifest，并在 SQLite 注册表保存索引；
- 历史研究表标记为 `HISTORICAL_DIAGNOSTIC`，组合候选标记为 `FORWARD_CANDIDATE`，正式影子信号标记为 `SHADOW_PAPER`；
- 综合组合的每个信号和订单通过不可变业务键绑定到具体模型版本；
- `/api/model-registry` 返回版本、证据产物和信号/订单绑定，前台策略研究页提供版本审计视图。

当前边界：本阶段的 `SHADOW` 表示 MoneyMore 正式模拟账户版本，不代表实盘批准；华泰 QMT 接入前不会产生实盘生命周期版本。

### M4.12 完整组合归因——已完成首版
