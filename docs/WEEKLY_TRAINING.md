# Qlib 每周自动训练

本地 API 启动后会同时启动每周训练调度器。计划时点为每周六 09:00（Asia/Shanghai）。调度器按“最近一个已经到期的周六”生成唯一周期键，因此计划时点电脑未开机时，下次启动服务会自动补跑。

自动训练使用独立 Python 子进程和本地 CUDA（可用时），状态写入 `state/qlib-training.sqlite3`，完整输出写入 `logs/training/YYYY-MM-DD.log`。

候选模型按周隔离保存在 `state/qlib-challenger/candidates/YYYYMMDD/`，不会覆盖当前影子账户使用的模型，也不会自动晋级。候选训练使用扩展训练窗及最近各 126 个成熟交易日作为验证集和测试集。

状态接口：`GET /api/weekly-training`。训练失败或进程中断不会将该周期标记完成，调度器后续检查会重新发起。

训练完成后，每日流水线会把最新候选接入独立账户 `qlib_candidate_YYYYMMDD`。候选排行榜、研究门禁、独立持仓、委托、成交、净值及与当前模型的共同日比较统一由 `GET /api/qlib-challenger` 的 `candidate_observation` 返回，并展示在“Qlib挑战者”页面。候选观察不构成自动晋级；旧候选账户和报告永久保留。

候选采用并行版本队列：每日流水线持续运行所有尚未达到60个版本共同日的候选。计数只要求该候选、因子基线和当前挑战者三者在同一交易日均有快照，不要求其他候选参与。新版本不会重置旧版本；20个共同日进入初评，60个共同日冻结该版本证据和待处理买单，等待人工正式评审。
