# 交易连续性与故障补偿协议

当前为模拟盘；本协议定义将来接入华泰 MiniQMT 交易账户时的安全边界，**不代表已启用实盘自动交易**。

## 两种补偿不能混为一谈

- 模拟盘缺口：可以用带来源标识的历史分钟线做反事实回放，记录为“估算回放”，不能伪称实时成交。
- 实盘缺口：过去的成交无法补造。恢复后必须以券商账户的实际资金、持仓、当日成交及未完成委托为准，重新求当前差额，只在当前交易时段下单。

## 恢复状态机

```text
故障发现 → 冻结新委托 → MiniQMT 重连
    → 两次独立券商快照确认 → 委托/成交/持仓对账
    → 处理未完成或结果未知委托 → 取最新生效目标
    → 当前持仓差额规划 → 卖出阶段 → 再查券商快照
    → 买入阶段 → 券商回报核验 → 目标收敛或显式残差告警
```

任何阶段状态不确定时停在原地，不能用重试次数替代券商确认。尤其是下单调用超时，结果可能是“已接受但未收到回包”；必须凭客户端引用和券商委托查询确认，不能直接重发。

## 规划器与幂等流水

`src/moneymore/execution_continuity.py` 的 `build_recovery_plan` 是只读纯函数。输入必须来自最新生效目标和券商可信快照：账户资金、逐证券总持仓/可卖数、全部未完成委托、实时行情及时间戳、交易日历、风险状态、对账结果。规划器拒绝断连、单次或过期快照、未对账、仍有未完成委托、过期行情及非交易时段；卖单只使用可卖数量；未收到卖出成交确认前不预支卖出款。资金不足且没有策略优先级时，禁止按代码顺序随意抢占预算。

`RecoveryJournal` 在发送前以确定性的 `intent_id` 原子预约。重复调用不会生成第二次可发送机会；超时标记为 `UNKNOWN`，等待券商查询和人工/适配器确认。它是交易接口未来必须使用的底层约束，不是发送器。

## 华泰交易适配器待满足的验收门槛

1. 只读查询资金、持仓、委托、成交，并证明账户和交易日一致；回报乱序、重复回报、分页与重连要有测试。
2. 持久化客户端引用与券商委托编号映射；未完成委托先查询或撤单，撤单请求返回不等于撤单完成，须再次查询确认。
3. 从冻结到恢复的故障演练覆盖 MiniQMT 退出、进程重启、网络断连、请求超时但委托已被券商接受、SQLite 锁、涨跌停、T+1 可卖不足与资金不足。
4. 每个场景验证“最多一次有效提交、不会反向交易、不会把历史信号冒充当前目标、账本和券商一致”。连续稳定模拟至少 20 个交易日后，另行审议实盘开关与下单限额。

华泰/迅投接口的委托查询、异步撤单等能力需在交易适配器内按实际 SDK 版本核验；当前 QMT 桥接只提供行情，不导入交易模块。
